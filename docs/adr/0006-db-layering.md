# ADR-0006: DB 3層化（raw / core / mart）

- **Status:** Accepted
- **Date:** 2026-06-16
- **Deciders:** @yamandesu44

---

## Context

以下の要件を同時に満たすデータ設計が必要:

- PCI 計算式・予測モデルが変わったとき、**過去データを再計算**できること（ADR-0004 / 0005）
- JV-Link 原文データを**改変せず保持**したい（取り込みの監査・リプレイ）
- 分析結果に `formula_version` / `model_version` を紐付け、世代管理したい
- 過去5年分（将来10年）の大量データに耐えること（ADR-0002）

---

## Decision

**raw / core / mart の3層**に分離する。

```
┌──────────────────────────────────────────────┐
│ raw 層   JV-Link 原文（固定長レコード）          │
│          追記のみ・改変禁止・リプレイ可能          │
│          例: raw_jvdata                         │
├──────────────────────────────────────────────┤
│ core 層  正規化済みドメインデータ                 │
│          races, race_entries, horses, ...       │
├──────────────────────────────────────────────┤
│ mart 層  分析結果（再計算可能）                   │
│          predicted_pace, pace_fit, ...          │
│          formula_version / model_version 付き    │
└──────────────────────────────────────────────┘

raw → core : パース・正規化（取り込みバッチ）
core → mart: PCI算出・予測（分析バッチ、式/モデル変更時に再実行）
```

### 各層の責務

| 層 | 責務 | 改変 | バージョン |
|---|---|---|---|
| **raw** | JV-Link 原文の保全。監査・再パースの源泉 | 追記のみ | — |
| **core** | 正規化された「事実」。レース・出走馬・成績・マスタ | 取り込みで更新 | — |
| **mart** | PCI・想定RPCI・PAI 等の「分析結果」 | 再計算で洗い替え可 | `formula_version` / `model_version` 必須 |

### 大量データ対策

- `races` / `race_entries` は**開催年でレンジパーティション**（5年→10年へ拡張可能）
- 分析用インデックス: `(競馬場, 距離, 馬場状態)`、`(ketto_num, 開催日)` 等

### 再計算の原則

- 式・モデルを変えたら、core を入力に mart を**新しい version で再生成**
- 旧 version の mart は当面残し、比較・ロールバック可能にする
- raw を保持しているため、core の再パースも可能（パーサ修正時）

詳細スキーマ: `docs/design/03-data-model.md`

---

## Consequences

**ポジティブ:**
- 式・モデル改修時に過去全件を安全に再計算できる
- 取り込みの監査証跡（raw）が残る
- 分析結果の世代管理（version）が一貫する

**ネガティブ:**
- ストレージ使用量が増える（raw + core + 複数 version の mart）
- 層間の変換バッチを保守する必要がある

**緩和策:**
- 古い mart version は保持期間を定めて削除（運用ポリシー）
- raw は圧縮保存も検討
