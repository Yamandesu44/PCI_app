# ADR-0001: アーキテクチャスタイル — モジュラーモノリス + レイヤードDDD

- **Status:** Accepted
- **Date:** 2026-06-16
- **Deciders:** @yamandesu44

---

## Context

MVP最短公開を優先しながら、以下の将来要件に耐えられる設計が必要:

- 機械学習モデル（LightGBM）によるRPCI予測への差し替え
- コース補正・馬場補正・騎手補正の追加
- 将来的なサービス分離の可能性

選択肢:

| 選択肢 | MVP速度 | 将来拡張性 | 複雑度 |
|---|---|---|---|
| シンプルモノリス（層なし） | ◎ | ✕ | 低 |
| **モジュラーモノリス + レイヤードDDD** | ○ | ○ | 中 |
| マイクロサービス | ✕ | ◎ | 高 |

---

## Decision

**モジュラーモノリス + レイヤードDDD** を採用する。

### 層構成と依存方向

```
┌─────────────────────────────────────┐
│  presentation  (FastAPI routers)    │
├─────────────────────────────────────┤
│  infrastructure  (SQLAlchemy, etc.) │
├─────────────────────────────────────┤
│  application   (ユースケース)         │
├─────────────────────────────────────┤
│  domain        (外部依存ゼロ)         │ ← ★コアの王冠
└─────────────────────────────────────┘
```

依存方向: 上 → 下のみ。下から上への依存は禁止。
`domain` 層は標準ライブラリのみ（SQLAlchemy・Pydantic・外部パッケージ禁止）。

### 境界づけられたコンテキスト

| コンテキスト | 責務 |
|---|---|
| **Pace Analysis** | PCI / RPCI / PCI3 / 脚質 / PAI（ドメインの王冠） |
| **Racing Data** | Race / RaceEntry / Horse / Jockey マスタ |
| **Data Acquisition** | JV-Link 取り込み（別プロセス。ADR-0002参照） |
| **Forecast** | 未確定レースへの予測適用・展開シナリオ・説明生成 |

### 強制手段

- `import-linter` を CI に組み込み、依存方向の逆流を自動ブロック
- `mypy --strict` で型安全を強制

---

## Consequences

**ポジティブ:**
- 単一デプロイユニットでMVP開発速度が高い
- `domain` 層が純粋Pythonのため、MLモデル差し替えが容易
- コンテキスト境界が明確なため、将来のサービス分離が可能
- テストが書きやすい（domainは外部依存なし）

**ネガティブ:**
- 横断的な変更で複数レイヤーを触る必要がある
- 単純なCRUDにしては構造が重い

**緩和策:**
- 単純なCRUDはapplication層を薄くすることで対応（過剰設計を避ける）
