# ADR-0004: PCI / RPCI / PCI3 計算式の隔離方針

- **Status:** Accepted
- **Date:** 2026-06-16
- **Deciders:** @yamandesu44

---

## Context

PCI / RPCI / PCI3 は本プロダクトの中核指標である。これらの計算式について、以下の事情がある:

- 計算式は**公開情報・書籍・TARGET表示値を参考**に実装する
- TARGET 独自補正式の**完全再現はMVPの目標としない**
- マジックナンバー（係数・丸め規則）を含む可能性が高く、初版が確定とは限らない
- 将来、TARGET との差分検証を経て**独自補正の導入を許容**する
- 式が変われば過去データの再計算が必要になる

このため、計算式が「あちこちに散る」と、係数1つの修正で全面改修が発生するリスクが極めて高い。

---

## Decision

### 1. 唯一の真実の場所（Single Source of Truth）

PCI / RPCI / PCI3 の計算は **`apps/api/src/pci/domain/pace/pci.py` だけ**に書く。

- 他のどの層・モジュールからも式を直接書かない（呼び出しのみ）
- domain 層の純粋関数として実装（外部依存ゼロ・標準ライブラリのみ）

### 2. PCI 概念式（MVP初版・`formula_version = "pci-v1"`）

記号: 距離 `D`(m)、走破タイム `T`(秒)、上がり3F `A`(秒)。

```
前半区間   = (D - 600) m を (T - A) 秒
前半1Fタイム = (T - A) / ((D - 600) / 200)
上がり1Fタイム = A / 3
比率 r       = 前半1Fタイム / 上がり1Fタイム
PCI = 50 を基準に r を指数化（係数・丸めは公開情報に合わせて pci-v1 で確定）
```

方向性（不変条件としてテストで固定）:
- 均等ペース（前半1F = 上がり1F）→ PCI ≈ 50
- 上がりが相対的に速い（後半が速い=スロー）→ PCI > 50
- 前傾ラップ（前半が速い=ハイ）→ PCI < 50

> 具体的な係数・丸め規則は実装PRで公開情報を参照して確定し、その出典をコミットメッセージとコード docstring に明記する。

### 3. バージョニング

- 全算出結果に `formula_version`（例 `"pci-v1"`）を付記する
- 式変更時は新バージョン（`"pci-v2"` 等）を発行し、**mart層を再計算可能**にする
- 独自補正を入れる場合も `formula_version` で区別する

### 4. ゴールデンテスト必須

- `apps/api/tests/unit/domain/pace/test_pci_golden.py` に手検証済みの入出力を固定
- 式変更時は**ゴールデンテストを必ず更新**し、変更根拠をコミットメッセージに記載
- プロパティテスト（hypothesis）で上記の不変条件を検証

### 5. TARGET 差分検証ハーネス（Should）

- TARGET 表示値（許諾範囲のサンプル）と自社 PCI/RPCI を突合する検証スクリプトを `apps/api/tests/` 配下または `apps/api/scripts/` に用意
- 完全一致を目標とせず、**差分の傾向把握と独自補正導入の判断材料**とする

---

## Consequences

**ポジティブ:**
- 係数修正が1ファイル + ゴールデンテスト更新で完結
- `formula_version` により式改修の影響範囲を追跡可能
- 独自補正の導入が安全（バージョン分離・再計算可能）

**ネガティブ:**
- すべての算出経路を pci.py 経由に強制する規律が必要

**緩和策:**
- CLAUDE.md に「式は pci.py だけに書く」を明記
- コードレビューで式の直書きを禁止
