# 設計書 07: 技術的リスクと残課題

## 1. 技術的リスクと対策（優先度付き）

| 優先 | リスク | 影響 | 対策 |
|---|---|---|---|
| **P0** | JV-LinkがWindows専用COM（C1） | 取り込み層全体 | ingestion-workerをWindowsに物理分離。残りはLinux/クラウド。DBスキーマ/Ingest APIを契約境界に。開発はfixturesで進める（ADR-0002） |
| **P0** | JRA-VANデータの公開可否（C2） | 事業成立性 | MVPは個人利用・検証用途に限定。生データ非提供・独自指標のみ。将来「ユーザー各自のDataLab契約前提」へ移行できるよう取得層と表示層を疎結合化 |
| **P0** | PCI系の式・定数が公開情報依存（C3） | コア正誤 | 式を pci.py に隔離＋ゴールデンテスト＋formula_version。TARGET差分検証で裏取り（ADR-0004） |
| P1 | 想定RPCI精度（C4） | 完成判定 | 受入基準（MAE≤1.5/一致率≥60%）を明文化。ルールベースで説明可能な水準を確保。未達なら要因追加（ADR-0005） |
| P1 | 大量データ/5年バックフィル（C8） | 性能・初期投入 | 開催年レンジパーティション・冪等な取り込み・バッチ投入（ADR-0006） |
| P1 | 確定前/確定後の状態管理 | 予測と答え合わせの整合 | races.status + race_entries の NULL 許容で同一テーブル管理（データモデル設計） |
| P2 | PAI定義の暫定性（C10） | 手戻り | 暫定式＋model_versionで前進、設定で重み調整、実運用で正式化 |
| P2 | 将来MLの説明可能性 | 原則違反 | SHAP等で reasons 生成、ルールベースをフォールバック常設 |
| P2 | Windowsワーカー運用 | 可用性 | タスクスケジューラ/サービス化、取り込み失敗の監視・再実行 |

## 2. 後から手戻りが発生しやすい箇所 TOP5（重点）

1. **(P0)** 取り込み方式を後決定 → ingestion全書き直し。**S0でADR-0002を確定済み**。
2. **(P0)** PCI式をあちこちに実装 → 定数修正で全面改修。**pci.py隔離を死守**（ADR-0004）。
3. **(P1)** 出馬表(確定前)と結果(確定後)のデータ状態設計の曖昧さ → 予測と答え合わせが破綻。**status設計で対応**。
4. **(P1)** mart層に version 入れ忘れ → 改修影響が追えず再計算地獄。**初版から必須**（ADR-0006）。
5. **(P1)** domain の依存方向逆流 → ML差し替え不能。**import-linterでCI強制**（ADR-0001）。

## 3. 残課題・将来検討事項

| 課題 | 種別 | タイミング |
|---|---|---|
| 正式公開時のJRA-VAN規約適合性 | 法務 | 正式公開前（C2） |
| PAI正式定義の確定 | プロダクト | 実運用検証後（C10） |

| 地方競馬対応 | 機能 | 中央で価値実証後（C5） |
| 認証・課金・マルチテナント | 機能 | SaaS化フェーズ（C11） |
| バックフィル10年への拡張 | データ | 運用安定後（C8） |
