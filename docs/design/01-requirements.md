# 設計書 01: 要求整理

## 1. 価値提案

「PCIを読める上級者の暗黙知（今回の展開はこうなる／この馬が恩恵を受ける）を
**説明可能なアルゴリズム**に変換し、初心者でも展開予想を扱えるようにするSaaS」。

最重要価値は **TARGETの再現ではなく**「PCIを理解していない競馬ファンでも展開予想を活用できること」。

設計上の優先順位:
1. 展開予想精度
2. 説明可能性
3. MVP最短公開

（TARGET互換性は上記より優先しない）

---

## 2. コア処理パイプライン

```
過去走の通過順位・上がり3F・走破タイム
  → ① 脚質判定（各出走馬）
  → ② 想定RPCI予測（脚質構成・距離・コース・馬場から今回のペース予測）
  → ③ 展開シナリオ生成（ハイ/平均/スロー・隊列イメージ）
  → ④ PAI算出 → 展開合致馬抽出（恩恵馬／不利馬）
  → ⑤ 可視化＋説明（なぜ合致するかの根拠提示）
```

## 4. 確定した前提条件（C1〜C11）

| ID | 前提 | 設計への反映 |
|---|---|---|
| C1 | JV-LinkはWindows実行・ワーカー分離 | ADR-0002 |
| C2 | 個人利用・検証用途、生データ非配布、独自指標のみ公開 | API設計（生データ提供なし）、取得層と表示層を疎結合 |
| C3 | PCI/PCI3/RPCIは公開情報ベース、TARGET完全再現せず、差分検証＋独自補正許容 | ADR-0004 |
| C4 | 想定RPCI受入: MAE ≤ 1.5、展開3分類一致率 ≥ 60% | ADR-0005、テスト戦略 |
| C5 | JRA中央のみ（地方は将来） | 取り込みスコープ限定 |
| C6/C7 | 日次バッチ（前日夜〜当日朝）、最小契約、速報なし | ADR-0002、当日更新へ拡張可能設計 |
| C8 | 過去5年（→10年拡張可） | 年レンジパーティション（ADR-0006） |
| C9 | 脚質暫定ルール（番手率60%、非該当=自在） | running_style.py、閾値設定化 |
| C10 | PAI = 100 − RPCI差補正 − 距離補正 − 馬場補正、重み設定化 | adaptability.py、設定ファイル |
| C11 | 認証/課金/マルチテナントなし（将来追加可能に） | 認証ミドルウェアの差込口確保 |

## 5. 非機能要求

| 項目 | 要求 |
|---|---|
| 説明可能性 | すべての算出結果に `reasons: list[Reason]` を付与 |
| 再計算容易性 | raw保持・mart層は version 付きで再生成可能 |
| 型安全 | 型ヒント100%・`mypy --strict` 0エラー |
| 品質 | Ruff 0エラー、pytest green、import-linterで依存方向強制 |
| 疎結合 | 予測ロジックは戦略IFで差し替え可能（ML対応） |
| データ鮮度 | MVPは日次バッチ。当日更新へ拡張可能 |
| 認証 | MVPは認証なし。差込口のみ確保 |
